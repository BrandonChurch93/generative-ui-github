The idea

Dashboards are drawn once, for the questions someone expected. This one is drawn for the question you ask. Paste a public GitHub repo, ask what you want to know, and an agent picks components from a fixed catalog and composes an interface around that repo's data. The model decides what to show and what matters most. Code renders it from the same finished pieces every time, so an answer nobody designed still looks designed.

How it works

Every question runs the same five steps, left to right, in the order the screen draws. The twelve common questions match a template, and Haiku fills it in about 1.8 s. Anything else goes to Sonnet, which composes from the whole catalog in about 6 s. Either way the model writes only a composition. Code draws every piece of it.

Principles

Meaning, not values

The model sends tone, emphasis and density. Color, size and spacing come from the system, so one state always reads one way.

Nothing appears without a cause

Every piece draws, wipes, extends, slides, counts or blooms into place. Nothing fades in from nowhere.

Every enter has a reverse

A new answer runs its exits just ahead of its entrances. Pieces that survive morph in place.

Warm, light, quiet

One coral accent marks what the model chose. Everything else is warm ink on warm white.

What it does not do

No persona toggle
The question already says who you are. A maintainer and a first-time contributor ask different things and get different screens.
No chatbot
Answers are interfaces, not transcripts. The next question is a chip or one line in the tray.
No private repos
Public data only, so there is nothing to authorize and nothing to leak.
No accounts
Nothing to sign up for. The only thing kept is a cache of GitHub's public stats.
