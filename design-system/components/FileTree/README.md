# FileTree

The files a pull request touches, or the layout of a folder, as an indented tree with quiet guides, per-file counts in one right-aligned column and one selected file.

- The composer picks FileTree in `changes` mode to show where a pull request lands (beside a DiffView in a review screen, or alone to answer "how big is this change and where"), and in `overview` mode to show a folder's layout ("where would a new contributor start"). In a review screen the tree's selected file is the file the DiffView shows.
- Schema: `repo`, `mode` (`changes` or `overview`), `pr` for changes or `path` for an overview root, `title`, optional `selected` (the file the model is talking about), optional `open` (folders to expand; by default every folder in a PR of 20 files or fewer, otherwise only the folders on the selected file's path) and `emptyTone` (`neutral` or `good`). The model chooses the title, the file it points at and what starts open. The system decides the order (folders first, then files, alphabetical), folder compression, truncation, counts, indentation and every number.
- Card: `g-card` with a `g-head`: the title on the left; on the right the file count in `meta` and, in changes mode, the totals, which sit in the same right column as every row's counts. A card has no inner card.
- Row: one line, 26, 30 or 34px tall by density. Mono at the code size (12px). Files in `ink`, folders in `muted`. Folders are `<button aria-expanded>`, files are `<a href>` to their diff.
- Indent: 16px per level. A row is the 12px chevron (folders) or an empty 12px slot (files), `space-1`, a 16px icon, `space-2`, the name. Files keep the chevron's slot so every icon at one depth stacks.
- Icons: a folder and a file, inline stroke SVG at 1.5px with round caps and joins, in `muted`. They identify, so they stay; nothing else gets an icon.
- Guides: a 1px `line` rule for each open folder, under the parent's chevron, from just below the parent row to the bottom of its last child. The selected row's capsule covers its guide.
- Compression: a chain of folders that each hold one child folds into one row (`packages/next/src/server/app-render`), so a deep monorepo path costs one level, not five.
- Counts: the `tag` style in two right-aligned slots sized to the widest value in the tree, so plus signs, minus signs and digits stack in columns. Additions `good`, deletions `crit`, a zero in `muted`, minus as U+2212. A collapsed folder carries the sum of what it hides; an open folder shows nothing, because its files carry their own. In overview mode the column counts files, on collapsed folders only, in `muted`.
- Row shape: every row state draws one rounded shape, `radius-md`, inset `space-2` from the card edge and 1px clear of its neighbors. The text keeps the density's side padding.
- Hover: the system's row hover, the shape lifts onto `surface-tint` with no shadow. Tree rows have no hairlines, so there is nothing to hide.
- Selected: `surface-tint` plus a 1px `accent` edge (4.49:1 on its ground, above the 3:1 an indicator needs), the file icon in `accent`, the name at weight 500, `aria-current="true"`. The edge is what separates selected from hovered.
- Focus: the 2px `focus` ring at 2px offset, drawn on the shape so it never clips against the card edge.
- Truncation: in the middle, by whole words, never mid-word. Split the name at `/`, `-`, `_` and `.`, then drop the token nearest the center until it fits, and show the gap as a `muted` ellipsis. So folders keep their first and last segment (`packages/next/…/server/app-render`) and files keep their first word and their extension with the word before it (`get-css-…-link-tags.tsx`). The start says what it is, the end says what kind. Mono makes the fit exact: characters times the advance. The full name stays in the tooltip and the accessible name.
- Density: side padding `space-4`, `space-5`, `space-6`; row height 26, 30, 34px; indent and type size never change.
- Skeleton: the header and eight rows as `line-soft` blocks at the real row height, indented like a tree, with count blocks on file rows. No guides and no accent until rows land. `aria-busy` and one sentence for screen readers.
- Empty: a pull request with no changed files. The header keeps "0 files" as data; one row below: neutral mark (or good, by `emptyTone`), "No files changed", and why in `meta`.
- Error: the header renders; one row with the unavailable mark, "Couldn't load files" in `ink`, the cause in `meta`, Try again in `accent-text` on the right. Never `crit`.
- Warming does not apply: GitHub returns 202 only from its `/stats` endpoints; pull request files and git trees answer at once or fail.
- Enter: the card rises; rows slide in from the left 70ms apart, top to bottom, and after the eighth row the rest arrive together; each guide extends downward as its folder's rows arrive; counts count up. Exit is the strict reverse.
- Update: a new file slides into place while its neighbors move with Flip; counts count to their new values. Morph: the selection capsule moves to the new row with a shared layout transition, never a fade.
- Reader actions: opening a folder slides its rows in from 10px left as its guide extends down, and the folder's rolled-up counts hand off to its files; closing is the reverse. Reduced motion collapses all of it to a 200ms opacity change.
- Accessibility: a `<nav>` with an `aria-label` from the title, holding nested lists. Every row has a visible `focus` ring. Folders are buttons with `aria-expanded`; files are links with `aria-current` on the selected one. Counts read as "45 additions, 19 deletions". Tab enters at the selected row; arrow keys move between rows and open or close folders, while every row stays a real button or link.
- Contrast: `muted` names 5.9:1 on surface and 5.48:1 on the `surface-tint` capsule; counts on the capsule `good` 5.38:1 and `crit` 6.96:1; the `accent` icon 4.49:1 against a 3:1 floor. Guides are 1.21:1 by design: indentation already carries the hierarchy, so the guide is a reading aid, not the only signal.
