# Select

A labeled single choice that looks like a TextInput when closed and opens a short menu of options, each with its count.

- The composer picks Select inside a Form when there are more than four options or their labels are long. Four or fewer short options go to FilterChips in single mode, so every choice stays in view.
- Schema: `label`, `options` (each a `value`, a `label` and an optional `meta` count), `value`, optional `placeholder`, optional `helper` and `required`. The model chooses the label and which options to offer from data it already fetched; counts come from that data, never from the model's prose. Option labels are sans: the system offered them, so they read as words, unlike a typed identifier.
- Closed: the TextInput field exactly (`radius-md`, `surface`, `line` border, 36, 40 or 44px, the same text inset) with a 16px chevron on the right at the text inset, inline stroke SVG, 1.5px, round caps, `muted`. Placeholder in muted, for example "Choose a milestone".
- Open: the menu is `surface`, `radius-md`, `line-soft` border, `card` shadow, `space-1` inside, `space-1` below the trigger and exactly the trigger's width. Rows are 32, 36 or 44px by density, padded so option text starts on the trigger's text edge. The active row (pointer or keyboard) is `surface-tint` at `radius-sm`.
- Chosen: a 16px check in `accent` (4.49:1 on surface-tint) that sits exactly under the chevron. Its slot is kept on every row so the counts line up. Counts are `meta` in muted, right aligned, for example "7 open".
- The chevron turns over while the menu is open. Past eight options the menu scrolls inside and type-ahead does the finding.
- Hover, focus, error and disabled match TextInput: `line-strong` border, the 2px `focus` ring outside the border, `crit-fill` border with a filled crit mark and a crit sentence ("Pick a milestone to ask about"), and a disabled field whose helper says why ("Milestones load once the repo checks out"). Messages are sans 12.5px; an errored trigger with focus shows its crit border inside the ring.
- Skeleton, empty and warming do not apply: the options arrive with the schema from data already on the screen. If the source has no options, the Select renders disabled with the reason in the helper ("No open milestones on this repo") instead of opening an empty menu.
- Motion: the menu unrolls from the trigger, a clip reveal top to bottom in 180ms (`power3.out`), its rows with it and no stagger. It closes in reverse in 120ms (`power2.in`). The chevron turns in the same time. Nothing bounces. Reduced motion shows and hides the menu with a 200ms opacity change.
- Accessibility: the select-only combobox pattern. The trigger is `role="combobox"` with `aria-haspopup="listbox"`, `aria-expanded`, `aria-controls` and `aria-activedescendant` on the active option, and focus stays on it. Its name is the label plus the value through `aria-labelledby`. Down or Up opens and moves, Home and End jump, typing finds, Enter or Space chooses, Escape closes without changing. On a coarse pointer the same styled trigger opens the native picker instead, so phones get their own wheel. Below 480px viewport width the trigger and option text go to 16px, matching TextInput, so iOS never zooms; desktop sizes stay as drawn.
