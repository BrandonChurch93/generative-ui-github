# DiffView

A unified diff for one file of a pull request, with ink text on quiet add and delete tints, a sign gutter that carries direction without color, and a calm fold when the file runs long.

- The composer picks DiffView when the answer is in the code itself: what the PR holding a release actually changes, the lines a failing check points at, the one file a question names. One file per DiffView. For a whole pull request it sits beside a FileTree, and the tree's selection decides which file it shows.
- Schema: `repo`, `pr`, `path` (one of the PR's files), optional `open` (default true; false renders the header alone), optional `lead` (the index of the hunk the model's sentence is about, shown before the fold; default the first hunk) and `emptyTone` (`neutral` or `good`). The model chooses the file, whether it starts open and which hunk leads. The system decides everything else: tints, word highlights, wrapping, where it folds, the size limit, truncation and every count.
- Header: `card-y` top, `row-y` bottom, the density's side padding, a `line-soft` rule. The chevron and path are one `<button>` with `aria-expanded`. Chevron 12px, 1.5px stroke, `muted`, pointing down when open and right when folded, the same chevron FileTree folders use. Path in mono at the code size: folders `muted`, the file name `ink` at weight 500, `space-2` after the chevron. Counts in the `tag` style on the right: additions `good`, deletions `crit`, a zero in `muted`, minus as U+2212.
- Hunk header: git's own `@@ -21,7 +22,7 @@ function` text, verbatim, in `meta`, `muted`. `row-y` above it, `space-1` below. Every hunk after the first gets a `line-soft` rule above its header.
- Line: JetBrains Mono 12px at every density on an 18, 20 or 22px line. Density adds air, never columns, so Prettier's 80 characters fit a 680px card. Ligatures are off so `===` and `=>` read as typed. Text is `ink` on every ground; there is no syntax color.
- Gutter: old and new line numbers at 11.5px in `muted`, right aligned in at least 3ch, `space-3` apart. The sign column holds `+` or `−` in `ink`, `space-3` before and `space-2` after. Numbers and signs are drawn from data attributes, so copying a selection copies code only.
- Tints: `diff-add` (`good` at 8% over surface) and `diff-del` (`crit` at 8%) run full bleed, card edge to card edge, behind the numbers and the code alike. The text on them stays ink.
- Word highlights: `diff-add-word` and `diff-del-word` (16%), `radius-sm`, no padding so the monospace grid holds. Only where a removed block and the added block right after it have the same number of lines; each pair is compared token by token and the changed tokens are marked, unless more than half the line changed, in which case the line tint says enough.
- Wrap: long lines soft wrap and the continuation hangs 2ch past the line's own indent, with no number in the gutter, so a wrapped line never reads as a new one. No horizontal scroll anywhere.
- Fold: past 40 rendered lines, the lead hunk shows and the rest fold into one row under a `line-soft` rule: "202 more lines hidden in 5 hunks" in the `label` size, `muted`, sans because it is prose, with Show all as a `g-link` in `accent-text` where a tag would sit.
- Over the limit: past 1,000 changed lines, or when GitHub omits the patch (lockfiles, generated files, binaries), a summary replaces the lines: neutral mark, "Too large to show here" in `ink`, the changed line count and the limit in `meta`, View on GitHub as a `g-link` in `accent-text`. The header still carries the real counts.
- Folded: the header alone, its bottom padding grown to `card-y` and its rule gone, so a stack of folded files reads as a list.
- Density: side padding `space-4`, `space-5`, `space-6`; header and hunk spacing follow `card-y` and `row-y`; line height 18, 20, 22px. Code size never changes.
- Skeleton: `line-soft` blocks at the real line heights, number blocks in both gutters and code blocks at code-shaped indents, so nothing reflows when the lines land. No tints, no signs, no accent until then. `aria-busy` and one sentence for screen readers.
- Empty: a file with nothing to diff, such as a rename or a mode change. The header keeps `+0 −0` as data; below it one row: neutral mark (or good, by `emptyTone`), "Renamed without changes", and what it was in `meta`.
- Error: the header renders with the path; one row with the unavailable mark, "Couldn't load this diff" in `ink`, the cause in `meta`, Try again in `accent-text` on the right. Never `crit`.
- Warming does not apply: GitHub returns 202 only from its `/stats` endpoints. Pull request files and compares answer at once or fail, so slow is a skeleton and failed is an error.
- Enter: the card rises; the path wipes in; hunks slide in from the left 70ms apart, each hunk as one block so a long file still lands in under a second; each tint extends from the left edge behind its line; the counts count up. Exit is the strict reverse: tints retract, hunks slide out left, the path wipes out, the card sinks.
- Update (a new push): new lines slide into place, dropped lines slide out, neighbors move with Flip, counts count. Morph (a rewrite keeps the DiffView but points it at another file): the path wipes to the new file, old hunks leave left as new hunks enter, and the card's height follows with Flip. If the file survives the rewrite, nothing replays.
- Reader actions: folding moves the body's height with Flip over 350ms (`power3.inOut`) while the chevron turns 90 degrees; Show all slides the hidden hunks in below as the fold row retracts, and focus moves to the first revealed hunk header. Reduced motion collapses all of it to a 200ms opacity change.
- Accessibility: the body is a `<table>` with a visually hidden caption naming the file and hidden column headers (old line, new line, change, code). Sign cells carry the words "added" and "removed", so direction never depends on color. Header counts read as "2 additions, 1 deletion". Word highlights are `<mark>`, which some screen readers announce. The toggle, Show all and View on GitHub are real buttons and links with the 2px `focus` ring at 2px offset. The header toggle is not a list row, so its hover is the chevron turning ink and the file name underlining, not the row lift.
- Contrast: `ink` 14.47:1 on `diff-add`, 14.15:1 on `diff-del`, 12.9:1 and 12.27:1 on the word highlights. `muted` line numbers 5.27:1 and 5.16:1 on the tints. Counts `good` 5.8:1 and `crit` 7.49:1 on surface; zeros in `muted` 5.9:1. Show all and View on GitHub in `accent-text` 5.38:1. The tints themselves sit at 1.12:1 against surface by design; the sign carries direction.
