# Timeline

> Build note (from `docs/schemas.md`, which wins on who supplies what): the model sends `kind`, `scope`, `limit`, `emptyTone`, `empty` and `dayAsk`; the system supplies the items. The schema line below describes the items the component receives.

Merged pull requests as events in time, newest first and grouped by day, joined by a 1px spine so the card reads as time rather than as a list of states.

- The composer picks Timeline to answer "what shipped" questions: "what merged into v16.2 in the last two weeks", "what landed since Monday". Pick StatusList when each item carries a state (pending, failing); pick Timeline when each item is an event with a time. The two share one card, header, side padding and mark column, so they sit in adjacent columns as one system.
- Schema: `title`, optional `meta` (the window, such as "last 14 days"), `items`, `emptyTone` and an `empty` line (`title`, `meta`). Each item is `number`, `title`, `author`, `mergedAt`, `additions`, `deletions` and `url`. At most 8 items; for more, the composer narrows the window.
- The model chooses the window, the title and the empty tone. The system decides everything about time: it sorts newest first, groups by day in the viewer's time zone, writes the day headings (Today, Yesterday, then weekday and date, such as Fri Oct 2), writes relative times (merged 2h ago), formats sizes and puts the accent on the newest node. The model never writes a time, a heading or a color.
- Header: `g-head`, the same as StatusList. Title in `card-title`, ink; the window in `meta`, muted; a `line-soft` rule, full width. `card-y` above, `row-y` below.
- Day heading: `meta` style at weight 500, muted, on the title edge (side padding plus 22px). `card-y` above and `space-1` below, so a heading sits closer to its rows than to the day before.
- Node column: 10px at the side padding, the same column as StatusList's marks. Titles start 22px in, so marks, nodes and titles line up across cards.
- Node: a 6px dot in `muted` with a 2px `surface` ring that parts the spine, centered on the title line. Merged is an event, not a state, so a node never wears a state color.
- Newest node: 8px in `accent` with the same ring. It is the timeline's endpoint and follows the chart endpoint spec; it is the only accent in the component.
- Spine: `line`, 1px, one element from the first node's center to the last node's. It runs behind the day headings so time reads unbroken, and it replaces row hairlines. With one item it has no length and never renders, so a single merge is one node and one row, never a dangling line.
- Row: title in `row-title`, ink, one line with ellipsis. Meta in `meta`, muted: #number · author handle · merged 2h ago. Size in the `tag` style on the title baseline: additions in `good`, deletions in `crit`, deletions right aligned in 4ch so both columns stack down the card.
- Padding: side padding is the density's shared value (`space-4`, `space-5`, `space-6`); rows take `row-y` (`space-2`, `space-3`, `space-4`) top and bottom, so a row is 52, 60 or 68px, the same as a StatusList row. Day headings take `card-y` above (`space-3`, `space-4`, `space-5`).
- Empty: one row in the timeline's rhythm with a 10px mark in the node column, no heading, no spine, no size. `emptyTone` is the model's call: `neutral` when nothing has happened yet (nothing merged into v17.0 yet), `good` when nothing is the good news (no reverts in the last 14 days).
- Skeleton: `line-soft` blocks at the real line heights: header, one day heading, three rows with 6px node blocks and a size block on the title line. No spine and no accent until data lands. `aria-busy` with a visually hidden "Loading merged pull requests."
- Error: the header still renders, then one row with the unavailable mark, the failure in ink, the cause in meta and Try again in `accent-text` on the title line, where the size sits. Never `crit`.
- Warming (the GitHub 202 wait): the header renders, then one row with the warming mark, a muted line naming what GitHub is counting and a meta line saying when it checks again. The card's bottom edge fills with the accent gradient, the same 3px as a Metric bar. Pull request lists never return 202, so this appears only when sizes come from a stats endpoint.
- Hover: the system's one row hover. The row lifts onto `surface-tint` as an inset rounded shape (`radius-md`, inset `space-2` from the card edge), no shadow. Timeline rows have no hairlines to hide; the node's ring takes the tint so the spine still parts cleanly.
- Focus: each row is a link to its pull request. A 2px `focus` ring at a 2px offset; the `space-2` inset keeps it inside the card and the heading's `space-1` keeps it clear of the heading above.
- Enter: the card rises; day headings and rows slide in from the left 70ms apart, top to bottom; the spine draws top to bottom from the newest node (draw, 1100ms, `power2.inOut`); each older node scales in as the spine reaches it (240ms, `power3.out`). The newest node pops with `back.out(2)` as its row lands: nothing bounces except the single point a component marks as the latest, and here that is the newest node.
- Exit: the reverse. The spine erases bottom to top (500ms), nodes shrink as it passes, rows slide out to the left, the card sinks.
- Update: a new merge slides in at the top while the rows below move down with Flip; the spine extends up to the new node (extend, 700ms); the accent passes from the old newest node, which shrinks to 6px and settles to muted, to the new one, which pops. A new day's heading slides in ahead of its row. Relative times change in place without motion.
- Morph: in a rewrite, rows are diffed by pull request number. Survivors move with Flip, dropped rows slide out, new rows slide in, and the spine extends or retracts to its new length rather than redrawing. The accent moves only if the newest item changed.
- Reduced motion: every move collapses to a 200ms opacity change; the spine and nodes appear at their final state.
- Accessibility: the card is a section named by its title; each day is a heading followed by an ordered list, newest first. Headings and relative times are `<time>` elements with the full date. Each row's link reads title, meta, then the size in words ("184 lines added, 42 removed"); the visual +184 −42 is hidden from assistive tech. Nodes and spine are hidden too: the newest is first in order, so the accent never carries meaning the text does not.
- Contrast: muted node 5.90:1 and accent node 4.84:1 on surface (4.49:1 on the hover tint), both over the 3:1 floor for marks. Every text color holds 4.5:1 on surface and on surface-tint; Try again in `accent-text` is 5.38:1 and 4.99:1. The `focus` ring is 13.04:1 on surface and 12.1:1 on the tint. The spine is `line` at 1.22:1 by design, like every hairline: it carries no information the nodes and order do not.
